# 食品法規適用性儀表板

正式網站由 GitHub Pages 發布：`main /docs`

## 維護方式

任何新增法規、修法更新、分類調整或前端功能修改前，請先閱讀根目錄的 `AGENTS.md`。

- `main`：正式發布版本
- `dev`：修改與驗證版本
- 法規資料：`docs/data/*.json`
- 模組登錄：`docs/data/manifest.json`
- 前端：`docs/index.html`、`docs/css/style.css`、`docs/js/app.js`

詳細維護原則、現行／歷史／未來規則、資料欄位與官方來源查證流程，請見 `AGENTS.md`。

## 衛生管理人員專區

保留原生 HTML／CSS／JavaScript 架構。主頁可切換至「衛生管理人員專區」，標題下方有兩個主要頁籤。法規內容不寫入 HTML 或 JavaScript；`hygiene-manager.json` 仍只負責哪些業者應設置。

新增工具資料登錄在 `manifest.json` 的 `tools.hygieneManager.files`，與原本 `modules` 分開，避免人員資格資料混入現行／歷史／未來法規清單：

- `hygiene-qualifications.json`：第4～7條資格路徑、證照名稱與訓練組合。
- `hygiene-documents.json`：第8條固定文件順序與動態資格證明名稱。
- `hygiene-industries.json`：工廠前提下的 HACCP 產品範圍、資本額與人數情境。
- `hygiene-major-policy.json`：TFDA 相關學類、第6條原列舉15項高職科別及函釋認定科別判讀政策。
- `hygiene-majors.json`：教育部114學年度校系、主要學類及高職群科代碼快照。

`js/hygiene-manager.js` 為資料驅動的查詢／文件組合邏輯，`js/hygiene-ui.js` 處理專區互動；`app.js` 共用 manifest 載入及來源。樣式仍使用既有 `style.css` 與 `mobile.css`。

### 法規判讀與範圍

2026-09-26 再次查核現行《食品製造工廠衛生管理人員設置辦法》、108/4/9「應置衛生管理人員之食品製造工廠類別及規模」及115/3/17 HACCP正式公告。資格與應備文件查詢以「業別」為必要條件，查詢列直接並排「業別、學歷／資格、證照、資本額」，不再設「更多條件」區塊。業別採固定選單；除公告九個具名業別與「其他食品製造業」外，另提供「即食餐食業（中央廚房食品工廠）」及「即食餐食業（餐盒食品工廠）」兩個便利選項。專科以上科系、學校、學歷、學類與代碼由獨立的「專科以上科系／學類代碼查詢」處理；該頁不顯示高職科別。

選擇「即食餐食業」時，系統會同時列出一般即食餐食、中央廚房食品工廠及餐盒食品工廠情境；直接選擇中央廚房或餐盒選項時則只顯示該特定情境。第5條的「中餐烹調乙級技術士證＋衛生講習120小時以上」只作為非HACCP中央廚房／餐盒情境的特別資格；屬應實施HACCP時，仍依第7條要求符合第4條並具HACCP附加資格。

第4條的專科以上相關科系與考試資格在搜尋列表合併為「專科以上／考試資格」一列；右側詳細內容以單選方式在第4條可用資格路徑間切換，其中學歷路徑標示為「專科以上相關科系畢業」。HACCP情境另可在第7條兩種附加資格間切換，應備文件會隨目前選擇即時變動；選擇食品技師、畜牧技師、獸醫師、水產養殖技師或營養師證書時，不會縮減第4條三種資格路徑，只會把第7條附加資格縮小到證書＋HACCP 30小時路徑；第4條「相關類科高等／相當特考」的應備文件仍使用法規通用的高等／相當特考及格證明名稱，不因查詢所選證照改寫成特定證書名稱。第6條仍只適用資本額未達3,000萬元且非屬應實施HACCP的情境；資格條件分開呈現「第6條原列舉高職科別（15科）」與「函釋認定科別」。餐飲技術科依109年7月10日 FDA 食字第1090019307號函認定得屬第6條第1款高職科別，但不改寫為法條第16科；其餘4年以上工作經歷與HACCP 60小時條件仍須同時符合。應備文件統一寫「高職第6條指定或函釋認定科別畢業證書」。第7條第二款的食品技師、畜牧技師、獸醫師、水產養殖技師或營養師證書一次列出，不再逐張證書使用下拉選單。

選擇「其他食品製造業」時，系統自動列出「其他食品製造業」非HACCP情境，以及食用油脂工廠、蛋製品工廠的HACCP特定情境。低酸性罐頭食品及酸化罐頭食品歸在「罐頭食品製造業」判讀，不列在其他食品製造業。查詢列表維持「業別／情境、學歷／資格、資本額條件、HACCP情境、法源、應備文件」六欄。

若同一HACCP或第4條情境不受資本額影響，未指定資本額時合併顯示為「不限」；第6條仍只顯示未達3,000萬元。詳細內容的「適用情境」完整帶入列表的業別／情境、學歷／資格、資本額條件、HACCP情境及法源。只有「應實施HACCP」結果才顯示「HACCP判定條件」，非屬應實施HACCP時不顯示該區塊。學歷／資格、證照、資本額均採AND篩選：選「高職」時只保留第6條高職資格路徑；選「專科以上／考試資格」時只保留第4條路徑；證照與資本額亦須同時符合。文件介面依需求統一為「申請書」，第8條原文是「申報書一份」。基本文件順序固定；第4條與第7條資格證明文件依右側目前勾選的資格路徑即時呈現。「目前選擇的資格條件」預設收合，需要時再展開。「專科以上科系／學類代碼查詢」只讀取 `education = 專科以上` 的校系紀錄，並可依二專、五專、二技、四技、學士、碩士、博士篩選。結果表不再重複顯示「專科以上」，移除「對應資格條文」欄；TFDA欄會同時呈現列舉科系名稱與所屬學類：與TFDA 109.06.19列舉名稱對應者以綠色標示「TFDA資料有列舉」，只有學類對應但沒有完全相同科系名稱者以橘色標示「需核對實際科系」。資料來源欄以「教育部校系｜教育部學類｜TFDA」短連結呈現。

### 快照更新

目前快照收錄7,966筆（專科以上6,356筆、高職與法定科別1,610筆），93個大專學類；「專科以上科系／學類代碼查詢」只顯示其中6,356筆專科以上紀錄，高職資料仍保留在快照供第6條資格資料使用。資料以114（2025–2026）學年度為基準，非即時招生名單，也未收錄歷年改制或每一系的所有相關細學類；因此不能把查無紀錄當作不符合。學校名稱只協助識別系所。

TFDA表列的是相關科系及所屬學類，不代表整個學類所有系所無條件認定。科系名稱比對採保守的候選名稱正規化：只移除可辨識的學制／班別尾綴（例如學系、科、碩博士班、在職專班、學位學程、二年制在職學位學程，以及底線後的專班標記），正規化後仍須與TFDA列舉名稱完全一致才標示「TFDA資料有列舉」；不使用寬鬆關鍵字包含判定。只有學類對應而科系名稱無法完全對應時標示「需核對實際科系」。高職以第6條指定科別名稱精確比對；其他科別的「不符合」僅針對第6條，不排除考試路徑。

1. 先讀 `AGENTS.md`、本文件、manifest及涉及JSON，於`dev`作業。
2. 查核 `sources.json` 的現行官方法規、TFDA科系表及教育部分類版本；不將草案當現行法規。
3. 從教育部官方來源下載分類架構、各校科系別學生數、高級中等學校科別資料，分別命名為 `bcode.xlsx`、`students.xlsx`、`vocational.xlsx`，放在專案外暫存目錄。
4. 安裝Python `openpyxl` 後執行 `python scripts/build-major-snapshot.py SOURCE_DIR YYYY-MM-DD`。程式不連網，輸出記錄原檔SHA-256以供追溯。若年度／分類版本變更，同步調整程式與來源 metadata，不只替換輸入檔。
5. 檢查科系／群科代碼、筆數、第6條原列舉15科完整性、函釋認定科別與狀態。法定科別通用紀錄不是各校招生證明。
6. 更新專區 `version`、`lastReviewed` 及來源；整站 `lastReviewed` 僅在所有既有法規模組重新校正後更新，避免把專區查核冒充全站重審。
7. 執行測試並檢視桌機／手機版面，在`dev`驗證通過後，以正常merge／fast-forward同步到`main`，禁止盲目force。

### 驗證

- `node --test tests/hygiene-manager.test.cjs`：JSON、manifest、來源引用、ID、現行／未來區分及資格／文件邏輯。
- 安裝Playwright及Chromium後執行 `node tests/browser-smoke.cjs`：六項需求案例、桌機／手機、欄位轉頁、動態文件、CSV、現行／歷史／未來及console／HTTP錯誤。可設 `BROWSER_EXECUTABLE` 指向既有Chromium系瀏覽器，`QA_OUTPUT` 指向截圖輸出目錄。
- 沒有建立第二份手機資料，亦未加入列印／PDF功能。

正式發布仍為 GitHub Pages `main /docs`。應先確認兩分支遠端沒有新變更，保留既有歷史再合併；部署後核對正式頁面的專區版本與manifest。

### 頁面日期

頁首「最後更新日期」及頁尾「資料版本」共用 manifest.version，使用 YYYY-MM-DD 純日期，不附加修訂序號；同日程式修訂以 Git commit 及靜態資源查詢參數識別。manifest.lastReviewed 保留全站法規校正紀錄，專區查核日期仍由 tools.hygieneManager.lastReviewed 提供。功能更新不推進未重新查核的法規日期。
